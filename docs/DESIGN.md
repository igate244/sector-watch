# セクター観測 — 設計書

Web アプリ設計の標準工程（要件定義 → 利用場面 → 情報設計 → 画面 → 技術選定 → データ設計
→ 実装 → テスト → デプロイ → 運用）に沿って、決めたことを残す。

## 1. 要件定義

### 目的
セクターごとに 5 銘柄ほどの株価を追い、値動きの原因を
**日経平均（地合い） / セクター / 個別** に分けて見る。
地合いやセクターに**つられて下がっただけ**の銘柄を、買い候補として拾う。

### 前提・制約
| 項目 | 決めたこと |
|---|---|
| 対象 | 日本株（東証）のみ。楽天証券で現物取引できる銘柄 |
| 取引 | 現物のみ（信用取引なし）、夜間取引（PTS）なし → 基準は**東証の終値** |
| 保有期間 | 数週間〜数ヶ月 → 主に見るのは **20 営業日**の下落。5 日と 60 日も並べる |
| 更新 | 1 日 1 回、平日 3 回: 昼 11:43（前場の途中経過）・夕方 16:41（終値）・夜 19:13（ニュース確認、予備 20:37） |
| 費用 | 実質 0 円。GitHub（公開リポジトリ）と Google AI Pro の特典（Cloud クレジット 月 $10）の範囲 |
| 運用 | スマホだけで完結させる。銘柄の変更もコードの変更も GitHub（Claude に頼む） |
| 通知 | なし（開いたときに見る） |

### 機能一覧（優先順）
- **必須**: 市場（日経平均・TOPIX）の動き / セクター別の動き / 銘柄ごとの要因分解 /
  買い候補・要注意の判定 / Gemini＋Google 検索による個別ニュースの確認 / 保有株の記録
- **あると良い**: 楽天証券の取引履歴 CSV 取り込み / Google ドライブへのバックアップ / 市場概況コメント
- **やらない**: 場中のリアルタイム更新、通知、自動売買、証券口座との連携

## 2. 利用場面

- **平日の夕方〜夜**: 通知は来ないので、自分で開いて「今日の買い候補」を確認する
- **気になる銘柄が下がったとき**: その銘柄を開き、下げの原因が地合い・セクター・個別のどれかを見る
- **買った・売ったあと**: 保有タブに記録する（または楽天の CSV をまとめて取り込む）
- **追う銘柄を入れ替えたいとき**: Claude に頼むと `config/watchlist.csv` を直して push。すぐ反映される

## 3. 情報設計

```
[今日]        データの鮮度 → 市場（日経・TOPIX）→ 買い候補 → 要注意 → セクターの温度表
[セクター]    セクターのカード一覧 → セクター詳細（チャート＋構成銘柄の要因分解）
[保有]        合計の評価損益 → 銘柄ごとの損益 → 取引の記録・CSV 取り込み
[設定]        銘柄リスト（GitHub）/ 再計算 / バックアップ / 指標の説明
（重ねて開く） 銘柄詳細：チャート・要因分解・判定理由・ニュース・自分の保有
```

- 下のタブは 4 つ。銘柄詳細とセクター詳細は上に重ねて開き、端末の戻るボタンで 1 段ずつ閉じる
- 期間の切り替え（1 日 / 5 日 / 20 日 / 60 日）は**親指の届く下の方**に置く
- 段階的に見せる: サマリー → セクター → 銘柄

## 4. 画面の決まりごと

- 上昇は**赤**、下落は**青**（日本の証券会社と同じ）。色だけに頼らず、必ず `▲` `▼` を付ける
- 比べる線は 3 本まで（銘柄・セクター平均・日経平均）。凡例と線の端のラベルを付ける
- チャートに触れた位置の値は、指で隠れないよう**チャートの上の固定欄**に出す
- 古いデータを最新と見間違えないよう、画面の一番上に「何日の終値か」を常に出す
- ライト・ダークの両方に対応

## 5. 技術選定

| 層 | 選択 | 理由 |
|---|---|---|
| 株価 | yfinance（GitHub Actions で実行） | stock-app で 3,900 銘柄の毎日取得が安定して成功している実績がある |
| 計算 | Python（pandas） | 既存の stock-app と同じ |
| ニュース判定 | **Gemini API ＋ Google 検索グラウンディング** | AI Pro の月 $10 クレジットで払える。検索は月 5,000 回まで無料 |
| ニュース（キーなし） | Google ニュース RSS | 無料・キー不要。見出しを並べるだけ |
| 銘柄リスト | リポジトリ内の CSV（`config/watchlist.csv`） | Claude が直接直せる。最初はスプレッドシートだったが、Claude から書き換えられないので 2026-11 に移した |
| 画面 | React + TypeScript + Vite + PWA | reading-log と同じ構成 |
| 保有の記録 | 端末内（IndexedDB / Dexie）＋ Google ドライブにバックアップ | 保有額は外に出さない |
| 公開 | GitHub Pages（公開リポジトリ） | 無料。計算と公開が 1 本のワークフローで済む |

Google の検索 API（Custom Search JSON API）は新規受付が終わっていて、2027-01-01 に終了するため使わない。
TOPIX と東証業種別指数は yfinance で取れない。TOPIX は連動 ETF（1306）で代わりにし、
セクターの動きは自分が選んだ銘柄の平均で作る。

## 6. 要因分解の計算

期間 h（1, 5, 20, 60 営業日）について、銘柄 i の騰落率 `R_i` を 3 つに分ける。

```
市場要因   M = β_i × R_日経
セクター要因 S = R_セクター(i を除く) − β_セクター × R_日経
個別要因   I = R_i − M − S          （3 つを足すと必ず R_i になる）
```

- `β` は直近 250 営業日の日次騰落率から求める（日経平均に対する感応度。0〜3 に丸める）
- セクターの騰落率は、**その銘柄を除いた**同じセクターの銘柄の騰落率の**中央値**（β も中央値）。
  自分自身が含まれると個別要因がセクター要因に混ざり、平均だと他の 1 銘柄の急落に引きずられるため
- セクター画面に出す「セクターの騰落率」は、全銘柄の等ウェイト平均（見たままの動き）
- セクターに 1 銘柄しかないときは S = 0

### 判定（20 日を主に見る）
| 判定 | 条件 |
|---|---|
| **買い候補** | 20 日で −6% 以下<br>かつ 市場＋セクター要因が −3% 以下<br>かつ 個別要因が −4% より小さい<br>かつ Gemini が個別の悪材料を見つけていない |
| **要注意（個別要因）** | 個別要因が −5% 以下で、市場＋セクター要因より大きい<br>または Gemini が個別の悪材料を見つけた |
| **様子見** | 下げているが主因がはっきりしない / 60 日高値から −10% 以下だが直近 20 日の下げは小さい / 5 日で −4% 以下 |
| **初動候補** | 上のどれにも当たらない銘柄のうち（下げている銘柄は対象外）<br>必須: 60 日高値から −3% 以内・終値 ＞ 50 日線 ＞ 200 日線・50 日線からの上離れ 15% 以下・60 日の上昇 50% 以下<br>判定: **直近 3 日で 60 日高値を更新** かつ **直前 10 日のボリンジャーバンド幅（20 日・±2σ）の最小が、過去 120 日の下位 25% 以内**<br>参考表示: 出来高（直近 3 日 ÷ 50 日平均）1.5 倍以上・20 日で日経平均より強い・セクター平均も日経平均より強い |

並び順は `z20`（20 日の下げが普段の値動きの何倍か）の小さい順。珍しい下げほど上に来る。

閾値は `pipeline/analysis.py` の先頭にまとめてある。投資助言ではなく、判断材料。

#### 初動候補の考え方と検証
- 根拠にしたもの: 52 週高値に近い銘柄ほどその後も強い（George & Hwang 2004）、
  値幅が縮んだもみ合いを高値方向に抜ける形（ミネルヴィニの VCP、ボリンジャーバンドのスクイーズ→エクスパンション）
- 公開中の 60 銘柄・直近約 100 営業日（出来高なし）で、条件の組み合わせを試した。
  「5 条件のうち 3 つ以上」のような数で決めると、その後 20 日の日経比はむしろ全体平均より悪かった。
  「高値更新＋値幅収縮」の組み合わせは 10 日後の日経比の中央値 +1.3%（全体 +0.6%）、勝率 54%（全体 51%）で、少しだけ良かった
- 期間も銘柄数も少ないので、効くと言える証拠ではない。だましが多い前提で、抜けた高値を割ったら撤退する使い方にする
- Gemini には「上昇のきっかけになる好材料があるか」を調べさせる（`news.judge_rise`、`kind: "rise"`）

## 7. データ設計

### 計算結果 `data/latest.json`（毎日作り直す）
```
generated_at, asof（終値の日付）, dates[]（直近 250 営業日）
market: { n225, topix, intraday{1|5|20: {interval, t[], n225[], topix[]}} }
                                   … 騰落率・終値の推移。intraday は市場カードのチャート用の分足（5分・15分・60分、先頭は前日の終値）
sectors[]: { name, ret{h}, dec{h:{m,s}}, beta, series[], codes[] }
stocks[]:  { code, name, sector, memo, last, ret{h}, dec{h:{m,s,i}}, beta,
             dd60, pos1y, z20, signal{label, reason, since?, days?, capped?}（since＝今の判定が始まった日、days＝何営業日目。成績表と同じやり直し計算から）, rise{score, hits[], near_high, ext50, vol_ratio}|null,
             news{kind: drop|rise, bad_news, good_news, …}, series[] }
market_comment: { text, sources[] }
watchlist: { source: sheet|fallback, edit_url, errors[] }
```

### 銘柄名とコードの対応 `data/codes.json`
楽天の取引履歴 CSV はコード欄が空のことが多いので、銘柄名からコードを引くために使う。

### 端末内（IndexedDB `sector-watch`）
```
trades: id, date, code, name, side(buy|sell), price, qty, account(NISA|特定|…), memo, key
```
`key` は取り込み時の重複を防ぐためのもの（日付・名前・売買・単価・株数）。
保有株数と平均取得単価は trades から毎回計算する（移動平均法）。

## 8. テスト

- `python -m pipeline.test_analysis`: 合成データで「地合いつれ安 → 買い候補」「個別の急落 → 要注意」になることを確認
- `npm run build`: 型チェック込みのビルド
- ローカルで実データを計算 → `npm run preview` で画面を確認

## 9. デプロイと運用

- 平日 11:43・16:41・19:13（予備 20:37、JST）に GitHub Actions が実行。Gemini は昼にひとこと 1 回、夜に銘柄の確認（最大 30 回）: 株価取得 → 計算 → ニュース判定 → 画面のビルド → Pages に公開
- main に push したときも同じ流れで公開する。ただしニュース判定は前回の結果を使い回し、Gemini は呼ばない
- Gemini の呼び出しは 1 回の実行につき最大 15 件（下げている銘柄だけ）＋市場概況 1 件。
  月に最大 350 回ほどで、検索の無料枠 5,000 回に十分収まる
- 60 日間コミットがないと GitHub が定期実行を止めるため、45 日ごとに空コミットする

### 古いデータで上書きしない
日経平均の最新日が欠けて取れることがある（Yahoo 側の都合）。銘柄のほうが新しい日まであれば日経平均だけ取り直し、
それでも公開中の `asof` より古ければ計算を中止する（Actions は赤になるが、公開中のものはそのまま残る）。

### 銘柄ごとの分足（data/intraday/<コード>.json）
`{ asof, h: { "1"|"5"|"20": { interval, t[], stock[], sector[], n225[] } } }`。
銘柄の詳細を開いたときだけ読む（いつもの latest.json は重くしない）。1 ファイル 16KB ほど（圧縮して 4KB）。
セクターは構成銘柄を「前の日の終値＝100」にそろえた平均。毎回作り直し、銘柄リストから外した銘柄のファイルは消える。

### 予定と決算（pipeline/events.py）
- `config/events.csv`: 大きな予定（FOMC・日銀・米雇用統計・CPI など）。日本時間で手書き。Claude に頼めば追記する
- SQ: 毎月第 2 金曜を自動（3・6・9・12 月はメジャー SQ）
- 決算: JPX「決算発表予定日」の Excel（期末の翌月上旬に掲載）から拾う。前回の結果を引き継ぎ、
  予定日が無い銘柄は「前回＋約 3 ヶ月」を目安（`next_est: true`、画面では「目安」と表示、予定一覧には出さない）
- latest.json: `events[] {date, time, region, level(大|中|決算), title, memo, kind(macro|sq|earnings), code?}`、
  `stocks[].earnings {last?, next?, next_est?, kind?}`

### 期間（アプリ全体で 1 つ）
画面下のバーで「1日・5日・1ヶ月・3ヶ月・6ヶ月・1年」を切り替え、今日・セクター・保有・銘柄詳細・セクター詳細が同じ期間で表示する（web/src/lib/period.ts）。
1ヶ月＝20 営業日、3ヶ月＝60、6ヶ月＝120、1年＝245。内訳（日経・業種・個別）は 3ヶ月まで（6ヶ月・1年は騰落率だけ）。
チャートの足は 1日＝5 分足、5日＝15 分足、1ヶ月＝60 分足（分足があれば）、3ヶ月〜＝日足。候補（20 日固定）と成績（5・20 日後）は期間に関係しない。
